# 铅冶炼 Kivcet 炉工作流设计

## 目标

在“铅冶炼 / 火法冶炼 / 基夫赛特炉”下提供与现有铜熔炼、吹炼相同的完整可用工作流：独立案例工作区、熔炼、熔炼设备选型、吹炼、吹炼设备选型和案例汇总。首版的计算字段、默认物料、默认产物、约束、热平衡、导入和导出均复用铜流程的既有模型；不在没有工艺数据的情况下将其改写为铅冶炼模型。

设备选型中的三维模型必须表达 Kivcet 炉的指定结构：高的反应塔、较矮的烟道塔、两者之间的水平连接通道、由反应塔顶部插入的喷枪，以及包覆喷枪的同轴水套。

## 范围

- 新增铅 Kivcet 的导航路由和以下工作页：项目工作区、熔炼、熔炼设备选型、吹炼、吹炼设备选型、案例汇总。
- 复制铜熔炼、吹炼已有能力：原料库和物相输入、配料、产出求解、约束编辑、热平衡、设备尺寸计算、三维模型、BOM、案例持久化、Excel/DOCX/MetCal 导入导出和汇总。
- 铅 Kivcet 案例与铜案例、锑案例使用不同的本地存储键、文件类型和缓存；任何读取、保存、重命名、导入或导出都不得落到铜案例。
- 新建 Kivcet 专属三维 viewer。既有侧吹炉 viewer 保持不变，继续仅服务现有铜/锑炉型。
- 暂不实现精炼、精炼设备选型，且不在左侧流程中暴露占位页。
- 暂不更改默认的铜物料名称、产物名称、物相、热力学参数、求解约束或 FLO 流名。它们是用户后续提供铅 Kivcet 工艺数据前的占位计算模型。

## 方案选择

### 方案 A：独立 Kivcet 工作流（采用）

从铜工作流复制其界面与计算能力，建立 `lead` 命名空间的页面、状态和工具模块。Kivcet 的路由、案例存储、导出标识和三维模型全部独立；计算默认值保持铜模型。

优点：用户后续替换铅模型、产物命名或 Kivcet 专属参数时不会回归铜流程；案例文件和浏览器缓存可追溯；三维设备可准确表达 Kivcet。

代价：首版会保留一组有意的代码平行结构，后续若铜/锑/铅需要共同演进再评估提取通用引擎。

### 方案 B：为铜页面增加 Kivcet 模式（不采用）

共享铜的案例和页面，只用方法标识切换标题与模型。它会使 Kivcet 与铜共享持久化形状和流程状态，后续铅参数变更易误伤铜数据或造成错误恢复。

### 方案 C：先重构为通用冶炼工作流（不采用）

一次性抽取铜、锑、铅的公共引擎。现有铜和锑工作流都有稳定、深度耦合的状态与导入导出行为，重构范围远大于本需求，且会推迟可用的 Kivcet 功能。

## 架构与数据流

1. `getSelectedSmeltAlgorithm` 识别 `pb / pyro / kivcet` 并返回新的 `lead-kivcet` 算法标识。
2. `MainContent` 懒加载 `LeadKivcetWorkflow`；它接收与铜工作流一致的 `activeSheet`、阶段跳转和案例标题接口。
3. Kivcet workflow 使用专属 `pb_kivcet_*` SheetId 和阶段导航，将工作区、熔炼、设备、吹炼、设备、汇总串联起来。阶段门禁沿用铜的顺序：完成熔炼产出和热平衡后才能设备选型；生成熔炼 BOM 后才能吹炼；完成吹炼和其 BOM 后才能汇总。
4. `leadKivcetProcessStageState` 使用复制后的铜计算状态结构和默认值，但保存为独立的 lead 类型、存储键和文件类型。MetCal/FLO 导入导出数据同样走 lead 包装层，避免触发铜的事件名或存储键。
5. Kivcet 设备页面继续使用既有设备尺寸和 BOM 计算结果，以保证首版“功能复制”可立即使用；其三维预览改为 `KivcetFurnaceViewer`。

## Kivcet 三维模型

`KivcetFurnaceViewer` 接收设备页已生成的设计尺寸，并只使用这些尺寸的稳定比例派生三维部件尺寸：

- 反应塔：位于左侧（从默认等轴视图观察），为较高的竖直长方体，作为主炉体。
- 烟道塔：位于右侧，为较低的竖直长方体，明确标识为烟道。
- 水平连接通道：位于两塔的中上部，采用横向长方体，端面与两座塔相接，不悬空也不穿出外壳。
- 喷枪：细长圆柱，自反应塔顶部沿竖直方向下插，末端进入反应塔内部。
- 水套：与喷枪同轴的中空圆筒，外径大于喷枪、长度略短于喷枪，从反应塔顶部包覆喷枪；喷枪和水套以不同颜色及独立图层显示。

查看器提供适合现有三维页面的旋转、缩放、平移、坐标轴视角切换、图层开关和悬停名称。模型初始视角须同时看见两个塔、连接通道、喷枪和水套；WebGL 不可用时显示尺寸和结构说明，不渲染空白区域。

## 错误处理与兼容性

- Kivcet 案例文件必须带独立的文件类型版本。读取到铜/锑案例或不匹配的导入数据时，显示明确错误而不尝试混用状态。
- 未完成前置工序时，复用现有门禁提示并阻止进入后续设备页或工序页。
- 默认模型内仍可能显示铜术语。这是本期明确接受的占位数据行为；Kivcet 页标题、案例和设备标签不得伪装成已完成铅冶金模型。
- 不修改当前铜、锑的路由、案例格式、设备 viewer 或 FLO 质量闭合逻辑。

## 验收标准

1. 从“铅冶炼 / 火法冶炼 / 基夫赛特炉”进入后，显示 Kivcet 项目工作区，不再显示“开发中”。
2. 可完成与铜对应的熔炼、熔炼设备选型、吹炼、吹炼设备选型和案例汇总；每页的计算、保存、恢复、导入导出和门禁均工作。
3. Kivcet 新建、重命名、保存、恢复和导出的案例不与铜或锑案例互相可见或覆盖。
4. Kivcet 设备页生成的三维模型清晰包含高反应塔、低烟道塔、二者的横向连接通道、顶部喷枪及其外围水套，并可独立控制这些图层。
5. 默认计算模型、产物名和参数与铜当前版本一致，且实现不宣称它们是铅 Kivcet 的工艺实测模型。
6. 对新增的纯函数和路由行为先编写失败的验证测试；所有新增验证、现有相关回归与前端 Vite 构建通过。
